# 旅游路线规划器

一个纯前端的旅游路线规划工具：在地图上打点、搜索地点、拖拽调整行程顺序，自动规划每两站之间的路线并显示距离和耗时，每个站点还能记备注和待办清单。数据保存在浏览器本地，不需要后端和账号。

基于 [高德地图 JS API 2.0](https://lbs.amap.com/api/javascript-api-v2/summary)，使用 Vite 构建，无前端框架。

## 功能

- **地图打点**：在地图上单击落下站点，自动识别名称和地址；也可以直接拖动标记微调位置
- **地点搜索**：左上角搜索框，输入关键词选择候选地点即可添加
- **路线规划**：驾车 / 步行 / 骑行三种方式，路线自动绘制，站点变化后自动重算
- **距离与耗时**：每两站之间显示距离和耗时，顶部显示全程总计
- **拖拽排序**：抓住卡片左上角的 `⋮⋮` 拖动，编号和路线同步更新
- **站点分类**：景点 / 餐厅 / 住宿，地图标记和卡片的颜色、图标随分类变化
- **备注与清单**：每个站点可写备注，并带有可勾选的待办清单
- **导出与分享**：
  - 导出 / 导入 JSON（换设备、备份用）
  - 生成分享链接（行程压缩在网址 `#` 后面，不经过任何服务器）
  - 存为图片（生成一张"行程单"）
- **本地保存**：所有改动实时保存在浏览器 `localStorage`

## 快速开始

需要 [Node.js](https://nodejs.org/) 18 或更高版本。

```bash
git clone https://github.com/mirrorxyjiang/travel-planner.git
cd travel-planner
npm install
npm run dev
```

启动后浏览器会自动打开 `http://localhost:5173/`。首次打开会弹出一个窗口，让你填入高德的 Key 和安全密钥，获取方法见下一节。

## 如何申请高德 API Key

高德对个人开发者免费，JS API 的日常使用额度足够个人规划行程使用。

### 1. 注册 + 实名认证

打开 [高德开放平台控制台](https://lbs.amap.com/)，用手机号或支付宝登录。首次会要求实名认证，选「个人认证」即可，免费，不需要营业执照。

### 2. 创建应用

进入「应用管理」→ 右上角「创建应用」→ 填一个应用名称（随便起，比如"我的旅游工具"），应用类型选"出行"之类，不影响使用 → 提交。

### 3. 添加 Key（最关键一步 ⚠️）

在刚建的应用下点「添加 Key」，在弹窗里：

- 服务平台一定选 **「Web端(JS API)」**（而不是"Web服务"！"Web服务"是给后端用的，前端网页地图用不了，会报错）
- 提交

### 4. 复制两个值

提交后页面会同时给出：

- **Key**（一串字母数字）
- **安全密钥 securityJsCode**

### 5. 填入工具

有两种方式，任选其一：

**方式一：在页面里填写（推荐）**
启动后在弹窗里分别粘贴 Key 和安全密钥，点「加载地图」。它们只保存在你自己浏览器的 `localStorage` 里，下次打开会自动沿用。

**方式二：写进环境变量（仅限本地开发）**
把 `.env.example` 复制为 `.env.local`，填入：

```
VITE_AMAP_KEY=你的Key
VITE_AMAP_SEC=你的安全密钥
```

重启 `npm run dev` 后，就不会再弹出填写窗口。`.env.local` 已被 `.gitignore` 忽略，不会被提交到仓库。

> ⚠️ **不要把 Key 提交到 GitHub，也不要在公开部署时使用方式二。** 以 `VITE_` 开头的环境变量会在构建时被写进前端代码，任何人都能在网页源码里看到。公开部署时请不要设置这两个变量，让使用者在页面弹窗里填写自己的 Key。

## 使用说明

| 操作 | 方法 |
| --- | --- |
| 添加站点 | 在地图上单击，或在左上角搜索地点后选择 |
| 调整位置 | 拖动地图上的标记 |
| 调整顺序 | 拖动卡片左上角的 `⋮⋮` |
| 在地图上定位 | 点击卡片左侧的编号圆点 |
| 更改分类 | 点击卡片里的「景点 / 餐厅 / 住宿」标签 |
| 切换出行方式 | 点击侧边栏顶部的「驾车 / 步行 / 骑行」 |
| 备份 / 换设备 | 底部「导出 JSON」，在新设备上点「导入」 |
| 发给别人看 | 底部「分享链接」或「存为图片」 |

### 关于分享链接

分享链接把整份行程压缩后放在网址的 `#` 后面，**不经过任何服务器**。对方打开链接即可看到你的行程，但前提是你已经把应用部署到了一个公网地址：本地的 `localhost` 链接发给别人是打不开的。对方打开时仍需要填入自己的高德 Key 才能加载地图。行程很长时链接会变长，超过约 8000 个字符时可能被部分聊天软件截断，这时建议改用 JSON 或图片。

### 关于图片导出

导出的是"行程单"（站点、备注、清单和路段耗时），不是地图截图。高德地图瓦片有跨域限制，直接截图会失败。

## 构建与部署

```bash
npm run build     # 产物在 dist/
npm run preview   # 本地预览构建结果
```

构建配置使用了相对路径（`base: './'`），`dist/` 可以直接放到任意静态托管：GitHub Pages、Vercel、Netlify、Cloudflare Pages 等。

### 部署到 GitHub Pages

仓库已内置自动部署配置（`.github/workflows/deploy.yml`），按下面三步即可：

1. 把代码推送到 GitHub 仓库的 `main` 分支
2. 进入仓库 **Settings → Pages**，把 **Source** 设为 **GitHub Actions**
3. 之后每次推送到 `main` 都会自动构建并发布，访问地址可在 Actions 运行结果或 Pages 设置页里看到

部署后的网页是公开的，使用者需要在页面弹窗里填入自己的高德 Key（见上文的安全提示）。

## 数据格式

导出的 JSON 结构如下，可以自己手动编辑后再导入：

```json
{
  "version": 2,
  "title": "周末杭州",
  "mode": "driving",
  "stops": [
    {
      "id": "lx3k9a2b",
      "name": "西湖",
      "cat": "sight",
      "lng": 120.1485,
      "lat": 30.2425,
      "memo": "浙江省杭州市西湖区",
      "checklist": [{ "id": "m4n8p1q2", "text": "买门票", "done": false }]
    }
  ]
}
```

- `mode`：`driving`（驾车）、`walking`（步行）、`riding`（骑行）
- `cat`：`sight`（景点）、`food`（餐厅）、`stay`（住宿）

## 常见问题

**页面一直空白或地图加载不出来？**
按 F12 打开浏览器控制台看报错。最常见的原因是：Key 的服务平台选成了"Web服务"，应该是「Web端(JS API)」；或者没有填写安全密钥。

**搜索或路线规划没有反应？**
检查 Key 是否已生效（新建的 Key 偶尔需要几分钟），以及是否超出了当日免费额度。

**路线和耗时是一段一段出现的？**
高德免费额度有并发限制，工具会逐段请求并间隔约 0.35 秒。站点越多，全部算完需要的时间越长；已经算过的路段会被缓存，调整顺序时只重算变化的部分。

**数据存在哪里？会不会丢？**
存在浏览器的 `localStorage` 里。换浏览器、换设备、清除浏览器数据都会导致丢失，建议重要行程定期「导出 JSON」备份。

**搜到餐厅或酒店，分类不对？**
目前新增站点默认分类是"景点"，需要手动点一下分类标签修改。
